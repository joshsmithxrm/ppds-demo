# PPDS Demo

Reference Dataverse solution (`PPDSDemo`, schema prefix `ppds_`) demonstrating the PPDS tooling and
ALM: plugins, web resources, a Functions app, an API, a console demo app, and the GitHub Actions pipelines.

## Build and test

CI builds through the `build-solution` action in `ppds-alm` and packs through its `pack-solution`
action; this repo does not show the exact commands those actions run. Local equivalents:

```
dotnet restore PPDSDemo.sln
dotnet build PPDSDemo.sln -c Release
dotnet test PPDSDemo.sln -c Release
```

There is no test project today. Tests run only in `pr-validate.yml` (`RUN_TESTS`, default true);
`ci-build.yml` and the deploy workflows build with tests off.

## Branches

- PRs to `develop` may come from any branch. `pr-validate.yml` rejects PRs to `main` unless the source
  is `develop` or `hotfix/*`, so feature and fix branches target `develop`.
- `ci-build.yml` runs on pushes to `develop` that touch `solutions/PPDSDemo/src`, `src/Plugins` or
  `src/PluginPackages`; `cd-qa.yml` deploys to QA after that build succeeds.
- `cd-prod.yml` deploys to Prod on pushes to `main` that touch `solutions/PPDSDemo/src`.
- Merge rules: `docs/guides/BRANCH_PROTECTION_GUIDE.md`, `docs/guides/HOTFIX_GUIDE.md`.

## Rules specific to this repo

- `src/Shared/PPDSDemo.Entities/` is generated (`<auto-generated>` headers). Regenerate with
  `tools/Generate-Entities.ps1`; do not hand-edit.
- `solutions/PPDSDemo/src/` is solution source that `ci-export.yml` exports from Dev nightly and commits
  to `develop`, stamping `version.txt`. Make customizations in Dev and export; do not hand-edit the XML.
- Plugin DLLs and `.nupkg` files under `solutions/**/PluginAssemblies` and `solutions/**/pluginpackages`
  are gitignored; CI builds and copies them in before packing.
- `src/Plugins/PPDSDemo.Plugins/registrations.json` comes from `tools/Extract-PluginRegistrations.ps1`
  and the `[PluginStep]` attributes. Change the attributes, then re-extract.
- Never commit credentials. `.env.*`, `.mcp.json`, `appsettings.Development.json` and `local.settings.json`
  are gitignored; copy `.env.example` or `.mcp.example.json`. The console app uses user secrets
  (id `ppds-dataverse-demo`).
- Schema objects and web resources use the `ppds_` prefix; web resources live in `src/WebResources/ppds_/`.
- Get an `IPooledClient` per operation with `await using var client = await pool.GetClientAsync()`; never
  keep one in a field. Disposal returns the connection to the pool.
- Read `client.RecommendedDegreesOfParallelism` rather than hardcoding parallelism
  (`DiagnosticsController`); use `IBulkOperationExecutor` for large batches (`CleanGeoDataCommand`).

More detail: `README.md`, `docs/README.md` (index), `docs/guides/LOCAL_DEVELOPMENT_GUIDE.md` (user
secrets), `docs/reference/` (plugins, solution structure, tools, PAC CLI).
