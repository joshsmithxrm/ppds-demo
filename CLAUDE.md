# PPDS Demo

Reference Dataverse solution (`PPDSDemo`, schema prefix `ppds_`) used to demonstrate the PPDS tooling
and as a starter template for ALM: plugins, web resources, an Azure Functions app, an API, a console
demo app, and the GitHub Actions pipelines that build and deploy them.

## Build and test

CI builds through the `build-solution` action in `ppds-alm`, which runs these against the solution file:

```
dotnet restore PPDSDemo.sln
dotnet build PPDSDemo.sln -c Release --no-restore
dotnet test PPDSDemo.sln -c Release --no-build
```

The test step only runs when a `*Tests.csproj` exists. None exists today, so it is skipped.
The Dataverse solution itself is packed in CI with `pac solution pack` (see `.github/workflows/pr-validate.yml`);
`dotnet build solutions/PPDSDemo/PPDSDemo.cdsproj` packs Unmanaged in Debug and Managed in Release.

## Branches

PRs from `feature/*` and `fix/*` branches target `develop`. `pr-validate.yml` fails any PR to `main`
that does not come from `develop` or `hotfix/*`. Pushes to `develop` build and deploy to QA; pushes to
`main` deploy to Prod. For merge rules see `docs/guides/BRANCH_PROTECTION_GUIDE.md` and
`docs/guides/HOTFIX_GUIDE.md`.

## Rules specific to this repo

- `src/Shared/PPDSDemo.Entities/` is generated by `pac modelbuilder` (files carry an `<auto-generated>`
  header). Regenerate with `tools/Generate-Entities.ps1`; do not hand-edit.
- `solutions/PPDSDemo/src/` is unpacked solution source that `ci-export.yml` exports from the Dev
  environment nightly and commits to `develop`, stamping `version.txt` and the solution version. Make
  customizations in Dev and export them rather than hand-editing the XML.
- Plugin DLLs and `.nupkg` files under `solutions/**/PluginAssemblies` and `solutions/**/pluginpackages`
  are gitignored. CI builds the plugins and copies them in before packing; do not commit them.
- `src/Plugins/PPDSDemo.Plugins/registrations.json` is produced by `tools/Extract-PluginRegistrations.ps1`
  from the `[PluginStep]` attributes in code. Change the attributes, then re-extract.
- Credentials are never committed. `.env.*`, `.mcp.json`, `appsettings.Development.json` and
  `local.settings.json` are gitignored; copy `.env.example` or `.mcp.example.json` instead. The console
  app reads .NET user secrets (id `ppds-dataverse-demo`).
- Dataverse schema objects and web resources use the `ppds_` prefix; web resources live under
  `src/WebResources/ppds_/`.
